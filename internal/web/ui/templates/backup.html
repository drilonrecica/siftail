Full backup

Full backups include retained application logs, configuration, credential hashes, source metadata, and security audit history. Browser sessions are always excluded, so restore requires a fresh sign-in.

Browser backups are written only to the server's backup directory, set by SIFTAIL_BACKUP_DIR (default /data/backups). Enter a plain file name, not a path; existing files are never overwritten. To write elsewhere, run siftail backup --output on the host. Scheduling and copying the verified artifact off-host remain operator responsibilities.

Optional. Letters, digits, dots, underscores, and dashes. Leave empty to name it siftail-full-<UTC time>.sqlite.

Configuration-only backup

Configuration-only backups include administrator and ingestion credential hashes, Servers, settings, and source names and aliases. They exclude application events and attributes, container observations, security audit history, diagnostics, and browser sessions.

Restoring this artifact replaces the database with that configuration and empty history; it is not a merge and not a complete log-history backup.

Optional. Written to the same backup directory. Leave empty to name it siftail-configuration-<UTC time>.sqlite.

Verify an artifact

Verification is read-only. It checks SQLite integrity, format and schema compatibility, required tables, completed metadata, type-specific exclusions, private permissions, and SHA-256 without applying or restoring anything.

A file in the backup directory. To verify an artifact elsewhere, run siftail backup verify on the host.

Restore

Restoring replaces the active database and requires the Siftail server to be stopped. On the host, run siftail restore --confirm RESTORE /path/to/backup.sqlite. The command preserves one verified siftail.db.rollback artifact and always requires a fresh sign-in.

Copy the managed rollback to another protected path before using it as a recovery artifact. Never copy only the live main database file while WAL mode is active.
