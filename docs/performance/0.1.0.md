# 0.1.0 ingestion baseline

**Measured:** 2026-07-28  
**Scope:** pre-release SFT-015 baseline; not a hardware-independent guarantee  
**Release action:** no tag or image was published

## Method and environment

- Host: Fedora Linux 7.1.4 x86-64.
- CPU: Intel Core i5-7500, four physical cores, 3.40 GHz nominal.
- Memory: 31 GiB host RAM; no container memory or CPU limit.
- Toolchain used: Go 1.26.5 linux/amd64 with CGO. The repository compatibility
  floor remains the version declared by `go.mod`.
- SQLite: bundled by `github.com/mattn/go-sqlite3` v1.14.48; WAL,
  `synchronous=FULL`, foreign keys on, 5 second busy timeout, memory temporary
  storage, incremental auto-vacuum, one writer connection, and four read
  connections.
- Benchmark command:

  ```bash
  go test -run '^$' -bench 'Benchmark(Normalize|DecodeBatch100|QueueAdmission|BatchWriterSQLiteCommit|BatchWriterSourceResolution|BatchWriterIdempotentRetry|HTTPCommitLatency|HTTPSustained100EventBatch)$' -benchtime=2s -benchmem ./internal/logs ./internal/ingest
  ```

- Queue/RSS command:

  ```bash
  go test -run '^$' -bench '^BenchmarkQueueSaturationRSS$' -benchtime=1x -benchmem ./internal/ingest
  ```

- Idle RSS was read from `/proc/<pid>/status` after a freshly built production
  binary created its database and both listeners plus the control socket were
  active. No request traffic or browser clients were present.

The fixtures intentionally cover structured metadata, JSON attributes,
multiline text, stable source event IDs, a warm stable source, cold source
discovery, single-event commits, and 100-event HTTP batches. The HTTP benchmark
uses the real handler, decoder, queue, coordinator, and SQLite database through
`httptest`; it does not include a TCP reverse proxy or Fluent Bit.

## Results

These are one-machine development measurements:

| Benchmark | Result | Allocated bytes/op | Allocations/op |
|---|---:|---:|---:|
| Canonical normalization | 19.888 µs/event | 8,667 | 212 |
| Decode and normalize 100 NDJSON records | 1.824 ms/batch | 924,665 | 20,113 |
| Queue admission and completion | 583.7 ns/event | 656 | 5 |
| Warm-source SQLite single-event commit | 190.941 µs/event | 5,808 | 109 |
| Cold source resolution plus commit | 1.056 ms/event | 11,109 | 231 |
| Stable-ID idempotent retry | 90.509 µs/event | 5,121 | 143 |
| HTTP single-event commit | 304.820 µs/request | 151,864 | 369 |
| HTTP 100-event sustained batches | 8,736 events/second | 1,453,640 | 26,619 |

The single-event HTTP sample reported p50 0.277 ms, p95 0.434 ms, and p99
0.605 ms. Those percentiles include normalization and durable SQLite commit but
exclude real network and proxy latency.

Idle production-process RSS and high-water mark were both 11,828 KiB with eight
threads. A queue filled to its default 32 MiB retained-byte cap using 8,192
representative events increased the Go benchmark process RSS by 40,292,352
bytes while its ledger reported 33,554,432 bytes. The roughly 6.4 MiB
difference is Go/container/object overhead and is why the byte ledger is a
capacity boundary rather than an RSS prediction. The queue test measures a
delta inside the Go test process; it must not be added mechanically to the
separately measured idle production RSS.

On this host the measured sustained path exceeded the 1,000 events/second
engineering target, and the measured HTTP p95 was below the 250 ms normal-load
target. These numbers do not promise equivalent results on other storage,
filesystems, CPUs, containers, or request distributions.

## Review and known limitations

- Privacy/security: no telemetry, outbound runtime calls, payload logging, or
  new credential exposure was introduced. Benchmark fixtures contain no real
  secrets. Token-bound Server identity and atomic rejection remain tested.
- Disk/latency: every acknowledged request performs a `FULL` synchronous
  transaction. The latency cost is deliberate; WAL and database files grow
  during benchmark runs inside temporary directories.
- Memory: resident and queue accounting remains bounded. RSS exceeds ledger
  bytes because Go objects, slices, channels, and allocator spans have overhead.
- Generic Fluent Bit compatibility remains best effort and limited to the
  documented tested JSON shapes.
- These are short local benchmarks, not the later production-container burst,
  disk-full, long soak, or multi-architecture release measurements.
- The 10-million-event query gate, browser clients, retention, backup, and
  release-container image measurements belong to later milestones.

The baseline is suitable for regression comparison under the review thresholds
in `ARCHITECTURE.md` §33.4. It is not a release certification by itself.
