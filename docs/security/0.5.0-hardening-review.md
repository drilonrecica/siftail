# 0.5.0 security and privacy hardening review

**Reviewed:** 2026-11-05
**Scope:** H2 of the 0.5.0 hardening plan (SFT-102 through SFT-110):
sign-in admission and throttling, aggregated sign-in auditing with reserved
capacity, the mandatory public URL with `__Host-` cookies and HSTS, session
lifetimes and "Sign out other sessions", session lookup under a degraded
database, the browser backup directory, the generated Fluent Bit input, the
`_FILE` secret contract, and the input hardening of return paths, forwarded
addresses, names, and the control socket
**Release action:** No tag, image, artifact publication, or public-release
claim

This review tests the single-administrator boundary as one system under
abuse and misconfiguration, as the 0.4.0 review tested the maintenance
features. The applicable boundary is the Siftail process, its owner-controlled
data directory, and the browser origin the operator configures. An actor who
controls the host, the environment, or the data volume already controls the
database; Siftail does not claim protection from a hostile host, root,
storage administrator, or offline database editor. Verification commands,
measured results, and the finding-by-finding record are in
`docs/release/h2-gate.md`; this document states what the controls are, what
was tried against them, and what remains.

## Threat and failure matrix

| Area | Adversarial condition | Control and evidence | Result |
|---|---|---|---|
| Parallel guessing | N concurrent sign-in requests evaluate N passwords before any throttle counts a failure | `Check` reserves the attempt and counts it before Argon2; one in-flight attempt per client key and per account key; a second concurrent attempt is `429` without hashing; every exit resolves the reservation once; 16 parallel wrong passwords yield one counted guess | Pass |
| Hash-slot starvation | A flood from rotating addresses queues on the two Argon2 slots ahead of the administrator | Bounded lanes (general 8, recent 2) with a 2-second wait and an immediate `429` on overflow; a freed slot passes straight to the next waiter in lane order; a client that signed in within 7 days is served first and cannot be rejected for general overflow; measured: the recent administrator signs in in about 140 ms during a 14,800-request flood | Pass |
| Remote lockout | One failure a minute from anywhere keeps the administrator's account locked | The account throttle never blocks a recent client, which stays bound by its own client throttle; the recent set is bounded at 64 keys and only a success adds to it | Pass |
| Throttle state erasure | Cheap, uncounted attempts on fresh usernames fill the throttle map so capacity eviction drops the locked account's delay | Found by this review and fixed: eviction ranks idle entries by value (no history, expired delay, active delay) before age, and in-flight entries are never evicted; erasing a delayed entry would need 4,096 keys with five counted Argon2 failures each inside 60 seconds | Fixed in SFT-111 |
| Username enumeration | Timing, status, text, or lane selection differs for an unknown or disabled username | Dummy Argon2 with production parameters, identical `401` text, identical throttle accounting; the lane depends only on the client key; `username` is `COLLATE BINARY`, so case variants are not extra account keys | Pass |
| Audit eviction and writer contention | 100,000 cheap rejections erase the real audit trail or hold the single writer | No rejection performs I/O; one aggregated `sign_in.rejected_summary` row per 5-minute window from an owned writer; `unauthenticated` rows have a 10,000-row sub-cap enforced only against `unauthenticated` rows through a trigger-maintained counter and partial index; 100,000 rejected attempts leave three rows and every privileged row intact | Pass |
| Hostile metadata | Attacker-controlled text reaches audit metadata through the aggregate | `top_client` is the throttle key, which is always a parsed address prefix or `unknown`; eight closed keys with canonical digits inside the 12-field, 2 KiB limits | Pass |
| DNS rebinding and insecure cookies | The allowed origin derives from `Host`, cookies lack `Secure` behind HTTPS, HSTS is never sent | `SIFTAIL_PUBLIC_URL` is mandatory for `serve` and `config validate`, validated as an exact origin; the origin check, cookie policy, and HSTS derive only from it, and no code reads `Host` or forwarded host or scheme headers; `__Host-siftail_session` with `Secure`, `Path=/`, no `Domain`, `HttpOnly`, `SameSite=Strict` on https; HSTS `max-age=31536000` on the UI listener only; a Host-derived `Origin` is refused with `403` end to end | Pass |
| Open redirect | A return path such as `/\evil.test`, `/%5Cevil.test`, `/%2F%2Fevil.test`, a control character, or an overlong encoding escapes the origin after sign-in | Raw and decoded forms rejected for backslash, C0, C1, DEL, Unicode whitespace, invalid UTF-8, absolute form, host, opaque form, and `//`; about 75 adversarial inputs probed, every accepted value redirects same-origin | Pass |
| CSRF and cross-site mutation | A cross-site form or fetch changes state, signs the administrator out, or revokes sessions | Every non-GET route under `Protect` requires the form content type, the exact configured origin from `Origin` or `Referer`, and a constant-time CSRF token derived from the session; logout and "Sign out other sessions" are POST only; the latter excludes the current session by server-side row ID and re-verifies it inside the transaction | Pass |
| Degraded database sign-out | A read-only, full, or closed database is treated as an expired session and the administrator is locked out of Status | `Lookup` separates `ErrInvalidSession` from `ErrSessionUnavailable`; `Protect` answers `503` with `no-store` and `Retry-After` and keeps the cookie; the idle touch is skipped on write failure and re-read on a lost race; sign-in after verified credentials reports a full or unavailable database honestly | Pass |
| Session lifetime | Legacy 14-day rows outlive the new 7-day absolute limit, or a revoked session keeps a Live stream | The absolute limit is applied from `created_at_us` in every predicate; Live re-checks the session every 5 seconds | Pass |
| Backup path abuse | A stolen session writes a database copy to an arbitrary path, probes file existence, or follows a planted symlink | The browser submits only a validated plain name inside `SIFTAIL_BACKUP_DIR`, resolved to a direct child of the real directory; an existing path of any type at the name is refused and hard-link publication cannot replace one; verification refuses symlinks and non-private files; missing, non-regular, and corrupt artifacts are the same failed state; no server path or submitted name is echoed; the CLI keeps arbitrary paths over the owner-only socket | Pass |
| Unauthenticated collector input | The generated Fluent Bit configuration listens on `0.0.0.0:24224` and forwards anything it receives under the server's valid token | Both templates and both committed fixtures bind `127.0.0.1` with an explanatory comment; the guide and UI explain `Shared_Key` and network policy for a non-loopback listener; the token is substituted only after matching its exact alphabet and the Server name is never interpolated | Pass |
| Token validity oracle | Status codes differ between a valid and an invalid ingestion token before authentication is complete | Same `401` for a missing, malformed, duplicate, or wrong token; `503` for every token when the database cannot answer; the token is checked before any body byte is read; constant-time comparison with a dummy compare on a miss; revocation re-checked inside the write transaction | Pass |
| Secret file handling | A `_FILE` secret is read from a FIFO, a writable file, or a symlink to something unexpected, or its content reaches logs or errors | Registry empty in 0.5.0, so every `SIFTAIL_*_FILE` is an unknown variable; the mechanism checks the path, then the opened descriptor, refuses non-regular and group-or-world-writable targets, bounds the read with `LimitReader`, trims only trailing CR and LF, and `Secret` redacts through every formatting path with the value behind a closure | Pass |
| Forwarded-address spoofing | A client chooses its own throttle key or audit address through `X-Forwarded-For` | Consulted only when the immediate peer is in a configured trusted network; header lines joined and walked right to left to the first untrusted address; parsed addresses only; IPv6 zones stripped and IPv4-mapped addresses unmapped before keying | Pass |
| Control socket availability | A failed `SO_PEERCRED` lookup ends the accept loop and the process | The failing connection is closed and accepting continues; the socket is mode 0600 and a stale socket is replaced only when owned by the current user and not a symlink | Pass |
| Supply chain | Reachable standard-library vulnerabilities in an unsupported toolchain | Go 1.27.3 with a `toolchain` line; `govulncheck` reports nothing the code calls; the module-level advisory for the unimported `openpgp` package persists as in 0.4.0 | Pass |

## Admission and throttling review

A sign-in attempt passes four gates before Argon2 runs: the throttle
reservation (counted at once, withdrawn only when no password was
evaluated), the per-key in-flight limit, the lane choice (recent or
general, decided by the client key alone), and the bounded hash queue. The
throttle's capacity bound was the one place where the reservation model
leaked: a withdrawn reservation left a zero-failure entry, and 4,096 of them
could age out the administrator's locked entry. The fix keeps the bound (so
memory stays finite under a flood of keys) and changes only the order of
eviction, so that the entries an attacker can create cheaply are the first to
go and a locked entry is the last. `docs/security/sign-in-throttling.md`
records the rule beside the measured values.

Two tradeoffs are documented rather than changed: a client that shares the
administrator's NAT or IPv6 /64 shares the recent-client exemption while
remaining bound by that shared client throttle, and a restart empties the
recent set until the next success.

## Audit capacity review

Unauthenticated traffic can create exactly one kind of audit row, the window
summary, and only through the owned writer. The reserved capacity is
structural: the only eviction an unauthenticated insert performs is
`DELETE … WHERE actor_type = 'unauthenticated'`, and if that cannot satisfy
the total cap the insert fails rather than touching a privileged row. The
consequence the owner should know is finding 3 of the gate report: once
privileged rows alone fill the table, a summary row evicts itself and the
guessing signal is lost silently. That is the ADR 0010 invariant working as
written, and whether to reserve a small minimum for summaries is a design
decision for the owner.

## Manual security checklist

- [x] No reviewed process-log call includes a password, session token,
  ingestion token, `Authorization` header, raw forwarded header, request
  body, or raw SQLite error; request logs carry method, route pattern,
  status, duration, and request ID only.
- [x] Sign-in failure pages and `429` pages use fixed text and never echo the
  username, password, or return path beyond the validated hidden field.
- [x] Every browser state change remains authenticated, same-origin against
  the configured origin only, CSRF-protected, body-limited, panic-recovered,
  and covered by the strict header set; the `503` session-unavailable page
  and fragment keep that header set and `no-store`.
- [x] The session cookie is never placed in a URL, log, audit row, or
  response body; the CSRF token is an HMAC over a constant keyed by it.
- [x] Audit metadata for sign-in aggregates, session revocation, and backups
  is closed-key and bounded; no attacker-controlled free text reaches it.
- [x] Browser backups and verification name only files inside the configured
  directory; artifacts are 0600 in a 0700 directory; no path or name is
  reflected.
- [x] Generated collector configuration binds loopback and embeds the token
  only after an exact-alphabet check; the Server name is never embedded.
- [x] No telemetry, analytics, CDN, external asset, update check, or
  automatic outbound API call was introduced by H2.
- [x] Throttle entries, the recent-client set, hash lanes, per-window client
  tracking, pending windows, and the unauthenticated audit sub-cap are all
  finite and independently enforced.
- [x] Failure responses and startup errors name variables and categories,
  never secret content, secret length, or server paths beyond the configured
  value the operator set.

## Recovery guidance

- Locked out after an attack: wait out the 60-second maximum delay from a
  network that has not failed recently, or sign in from the network of the
  last successful sign-in, which the account throttle never blocks. The CLI
  (`siftail admin reset-password`, `siftail sessions revoke-all`) is never
  throttled.
- `503` "could not check your session": the database is unavailable, not the
  session. Keep the browser open, follow
  `docs/operations/storage-full-recovery.md`, and retry; the same cookie
  works once the database answers.
- `serve` refuses to start: set `SIFTAIL_PUBLIC_URL` to the exact browser
  origin. A value that validates but refuses every sign-in with `403` is
  usually non-canonical (a zero-padded port, a non-ASCII host, an
  uncompressed IPv6 literal); write it the way the browser's `Origin` header
  would.
- Upgrading an https deployment renames the cookie once; every browser signs
  in again. Sessions created before the upgrade end 7 days after their
  creation at the latest.

## Verification record

The review ran on Fedora Linux 44 (Linux 7.2.10, four logical CPUs) with Go
1.27.3, Node.js 24.21.0, Playwright 1.64.1, go-sqlite3 v1.14.52, and
golang.org/x/crypto v0.58.0:

```bash
GOFLAGS=-count=1 make check
GOFLAGS=-count=1 make race-test
go run golang.org/x/vuln/cmd/govulncheck@latest ./...
make playwright
git diff --check
GOFLAGS=-count=1 go test -run 'Throttle|HashGate|Login' ./internal/auth
```

All commands passed on the final tree: `make check` in 28 s and `make
race-test` in 54 s with all 16 packages uncached and no race report; the
Chromium suite passed all 24 scenarios in 75 s on the final tree (and in
106 s on the first pass), including the four security scenarios (headers and logout, http cookie and sign-out-others, https
`__Host-` cookie with HSTS and origin refusal, uniform failures and the
fifth-attempt `429`); `govulncheck` reported no called-symbol or
imported-package vulnerability and the same module-only advisory as the 0.4.0
review. A first pass under heavy CPU contention and with `TMPDIR=/var/tmp`
failed timing-sensitive tests and the restore CLI test's socket path; both
are harness sensitivities recorded in the gate report, not product defects.

Three independent reviewers, given only the specifications and the files,
produced the findings and the invariant tables that the gate report records.
The one Medium finding was reproduced by a failing test before it was fixed.

## Residual limitations

- Host, root, environment, or volume compromise defeats every control here;
  the `_FILE` contract and the backup directory confine the browser, not the
  host.
- A client on the administrator's NAT or IPv6 /64 shares the recent-client
  exemption and lane. The shared client throttle still bounds it.
- After a restart the recent-client set is empty until the next successful
  sign-in, so the administrator competes in the general lane during a flood
  that starts before that.
- Unauthenticated sign-in auditing is a per-window aggregate: exact
  per-attempt timing is not retained, `top_client` is the most frequent of at
  most 1,024 tracked keys, a crash loses the open window, and a restart
  inside a window produces two rows for it.
- When privileged rows alone fill the 100,000-row audit table, a new
  aggregate evicts itself; see the gate report, finding 3.
- `SIFTAIL_BACKUP_DIR` is compared with the data directory lexically; an
  operator can alias them through a symlink, in which case the live files are
  still protected by the exists check but backups land beside them.
- `SIFTAIL_PUBLIC_URL` is validated as an origin but not canonicalized;
  non-canonical values fail closed into a sign-in lockout rather than a
  validation error.
- htmx's default inline indicator style produces a CSP violation on every
  page (SEC-16, SFT-123); the CSP is correctly blocking it.
- `govulncheck` reports the module-only advisory for the unimported
  `golang.org/x/crypto/openpgp` package; Siftail does not import it.
- Browser automation covers Chromium and axe. Manual assistive-technology and
  cross-browser review remain release-gate evidence, not a claim of universal
  accessibility.
