### SFT-050 — Build the minimal non-root multi-architecture image

**Status:** Done
**Milestone:** 0.5.0
**Depends on:** SFT-049
**Issue/PR:** — (direct maintainer implementation)
**Completed:** 2026-07-28
**Completion evidence:** Added a digest-pinned, deterministic multi-stage
Dockerfile for CGO-enabled `linux/amd64` and `linux/arm64` builds and a
Distroless Debian 12 runtime. The image contains one directly signaled Siftail
process running as `65532:65532`, one owner-writable `/data` volume, the Apache
license, glibc, CA certificates, timezone data, both declared listener ports,
and an explicit readiness health command. The bounded no-proxy health command
requires the exact local readiness response and returns only generic failure.
The exported-runtime inspection rejects shells, package managers, compilers,
Go/Node/npm, source, test, and browser artifacts. Both architecture smokes
created fresh databases, administrators, Servers, and one-time tokens; checked
unwritable and owner-mapped bind mounts; ran image health; ingested and browsed
History through a real session; observed a batch in the bounded queue during
SIGTERM; required both committed HTTP outcomes; restarted; and verified
persistence. amd64 ran natively and arm64 through a separately bind-mounted
static QEMU emulator because the test host had no binfmt registration.
Two timestamp-normalized no-cache amd64 builds reproduced image ID
`sha256:93cfacbdfe1995cac8805442b8d48bb424c7996d94c7ec9b687c2831745268b1`.
Final amd64/arm64 local image sizes were 37,202,267/46,821,738 bytes,
deterministically compressed Docker archives were 14,270,687/13,635,765 bytes,
and stripped binaries were 12,131,960/11,235,256 bytes. Native amd64 readiness
was 395 ms with 15,140 KiB RSS at readiness and after ten idle seconds; the
non-native arm64 QEMU observation is explicitly not a platform performance
claim. Digest-pinned Trivy 0.70.0 scans of both archives found zero fixable
high/critical vulnerabilities and no secrets; the full report and module-only
finding limitations are recorded. `make check`, `go test -race ./...`,
`shellcheck scripts/container-smoke.sh`, both final container smokes,
`govulncheck`, 19 Playwright tests, and `git diff --check` pass. Architecture,
README, and the container-image runbook document build inputs, metadata,
health/signals, footprint, licenses, security refresh duties, and platform
limits. No migration, runtime service, telemetry, privileged access, or public
image publication was added.

**Authoritative references:** `ARCHITECTURE.md` §§9, 34–35; `PRODUCT.md`
§§18, 19.5.

**Outcome:** Produce reproducible `linux/amd64` and `linux/arm64` images
containing one non-root Siftail process and no development runtime.

**Acceptance:**

- The image runs the production binary as non-root with one `/data` volume,
  both listeners, required CA/timezone support, and explicit health behavior.
- Node, package managers, compilers, browser artifacts, test fixtures, and
  source secrets are absent from the runtime stage.
- Version/build metadata is reproducible and contains no credentials or local
  paths; signals reach Siftail directly for graceful shutdown.
- Both architectures pass fresh database, ingestion, browser login/history,
  and queued-shutdown smoke tests.

**Verification:**

- Build and inspect both architectures, scan dependencies/image contents, and
  run production-container smoke and non-root volume-permission tests.
- Record compressed/uncompressed size, binary size, startup/idle RSS, build
  inputs, and supported platform limitations.

**Impact:** Adds production packaging and image metadata only. License and
security maintenance for every runtime layer are documented.

### SFT-054 — Measure the production container and 10-million-event query gate

**Status:** Planned
**Milestone:** 0.5.0
**Depends on:** SFT-053
**Issue/PR:** —

**Authoritative references:** `ARCHITECTURE.md` §§32–34; `PRODUCT.md` §§17,
19.5.

**Outcome:** Measure the shipped container against ingestion, query, latency,
memory, disk, and concurrency targets on realistic datasets through 10 million
events.

**Acceptance:**

- Measurements include idle/normal RSS, 1,000 events/s sustained, 5,000
  events/s burst, p95 commit latency, queue saturation, database growth,
  retention, backup, and concurrent session/read behavior.
- History plans and latency are reviewed at 100k, 1M, and 10M rows for primary
  filters, equal-time pagination, text search, details, and export.
- Hardware, filesystem, architecture, image digest, Go/SQLite settings,
  fixture distribution, commands, warmup, duration, and actual results are
  recorded.
- Hardware-specific numbers are not generalized; meaningful regressions or
  permitted measured limitations are explicit.

**Verification:**

- Run the documented production-container benchmark harness and retain machine
  readable summaries without committing databases or sensitive payloads.
- Repeat critical samples for variance and compare against prior 0.1/0.2/0.3
  evidence where methods are compatible.

**Impact:** Benchmark code and documentation. No tuning change is combined
without focused evidence and review of durability/resource consequences.

### SFT-055 — Add and run the bounded production soak procedure

**Status:** Planned
**Milestone:** 0.5.0
**Depends on:** SFT-054
**Issue/PR:** —

**Authoritative references:** `ARCHITECTURE.md` §§32–33, 36;
`PRODUCT.md` §19.5; `AGENTS.md` §29.

**Outcome:** Exercise ingestion, reads, Live, retention, sessions, maintenance,
restarts, and bounded failure recovery over a documented extended run.

**Acceptance:**

- The harness uses realistic mixed fixtures and bounded generators while
  tracking commit outcomes, ordering, deduplication, memory, goroutines, disk,
  WAL, latency, and errors.
- Scheduled scenarios include token/session changes, Live reconnects,
  retention, backup verification, graceful restart, saturation, and recovery
  from a controlled degraded condition.
- Cleanup is deterministic and the harness contains no real application data
  or external telemetry.
- Leaks, corruption, acknowledgement violations, unexplained growth, and
  high-risk failures block completion.

**Verification:**

- Run the documented pre-public soak duration in the production container and
  record host, image, configuration, workload seed, timeline, results, and
  limitations.
- Verify final integrity, backup restore, critical queries, race/stress suites,
  and cleanup.

**Impact:** Development-only harness and operational evidence. Resource
collection remains local and bounded.
