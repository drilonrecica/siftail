### SFT-050 — Build the minimal non-root multi-architecture image

**Status:** Done
**Milestone:** 0.5.0
**Depends on:** SFT-049
**Issue/PR:** — (direct maintainer implementation)
**Completed:** 2026-07-28
**Completion evidence:** Added a digest-pinned, deterministic multi-stage
Dockerfile for CGO-enabled `linux/amd64` and `linux/arm64` builds and a
Distroless Debian 12 runtime. The image contains one directly signaled Siftail
process running as `65532:65532`, one owner-writable `/data` volume, the Apache
license, glibc, CA certificates, timezone data, both declared listener ports,
and an explicit readiness health command. The bounded no-proxy health command
requires the exact local readiness response and returns only generic failure.
The exported-runtime inspection rejects shells, package managers, compilers,
Go/Node/npm, source, test, and browser artifacts. Both architecture smokes
created fresh databases, administrators, Servers, and one-time tokens; checked
unwritable and owner-mapped bind mounts; ran image health; ingested and browsed
History through a real session; observed a batch in the bounded queue during
SIGTERM; required both committed HTTP outcomes; restarted; and verified
persistence. amd64 ran natively and arm64 through a separately bind-mounted
static QEMU emulator because the test host had no binfmt registration.
Two timestamp-normalized no-cache amd64 builds reproduced image ID
`sha256:93cfacbdfe1995cac8805442b8d48bb424c7996d94c7ec9b687c2831745268b1`.
Final amd64/arm64 local image sizes were 37,202,267/46,821,738 bytes,
deterministically compressed Docker archives were 14,270,687/13,635,765 bytes,
and stripped binaries were 12,131,960/11,235,256 bytes. Native amd64 readiness
was 395 ms with 15,140 KiB RSS at readiness and after ten idle seconds; the
non-native arm64 QEMU observation is explicitly not a platform performance
claim. Digest-pinned Trivy 0.70.0 scans of both archives found zero fixable
high/critical vulnerabilities and no secrets; the full report and module-only
finding limitations are recorded. `make check`, `go test -race ./...`,
`shellcheck scripts/container-smoke.sh`, both final container smokes,
`govulncheck`, 19 Playwright tests, and `git diff --check` pass. Architecture,
README, and the container-image runbook document build inputs, metadata,
health/signals, footprint, licenses, security refresh duties, and platform
limits. No migration, runtime service, telemetry, privileged access, or public
image publication was added.

**Authoritative references:** `ARCHITECTURE.md` §§9, 34–35; `PRODUCT.md`
§§18, 19.5.

**Outcome:** Produce reproducible `linux/amd64` and `linux/arm64` images
containing one non-root Siftail process and no development runtime.

**Acceptance:**

- The image runs the production binary as non-root with one `/data` volume,
  both listeners, required CA/timezone support, and explicit health behavior.
- Node, package managers, compilers, browser artifacts, test fixtures, and
  source secrets are absent from the runtime stage.
- Version/build metadata is reproducible and contains no credentials or local
  paths; signals reach Siftail directly for graceful shutdown.
- Both architectures pass fresh database, ingestion, browser login/history,
  and queued-shutdown smoke tests.

**Verification:**

- Build and inspect both architectures, scan dependencies/image contents, and
  run production-container smoke and non-root volume-permission tests.
- Record compressed/uncompressed size, binary size, startup/idle RSS, build
  inputs, and supported platform limitations.

**Impact:** Adds production packaging and image metadata only. License and
security maintenance for every runtime layer are documented.

### SFT-051 — Add the supported Docker Compose deployment

**Status:** Done
**Milestone:** 0.5.0
**Depends on:** SFT-050
**Issue/PR:** — (direct maintainer implementation)
**Completed:** 2026-07-28
**Completion evidence:** Added a supported base Compose deployment with exactly
one directly signaled non-root Siftail service, one named `/data` volume, two
internal listener ports, readiness health, `restart: unless-stopped`, a
40-second stop grace around the default 30-second application drain, the
versioned `0.5.0` GHCR image default, and the fixed
`COOLIFY_APP_NAME=siftail-self` recursive-drain identity. The base publishes no
host ports; the separate local override publishes both listeners to
configurable loopback endpoints. Required UI and complete ingestion public
URLs fail during Compose interpolation, proxy trust is empty by default, and
the nonsecret environment example contains no administrator password,
ingestion token, or secret value. The Compose runbook covers local and
container-network proxy shapes, the Coolify consumption boundary without
promoting SFT-052, non-root volume ownership, shutdown timing, interactive
setup, backup-before-upgrade, schema-aware rollback, state-preserving `down`,
and deliberately destructive `down --volumes`.

Docker Compose v5.3.1 validated base and merged configurations and rejected
missing required URLs before container creation. The bounded amd64 smoke used
the locally built SFT-050 image through the rootless Podman 5.8.4
Docker-compatible API because this account could not access the host Docker
Engine socket. It created the administrator through two-line stdin, captured
the one-time token without printing it, proved the `65532:65532` process and
writable named volume, reached healthy readiness, committed ingestion,
authenticated and browsed History, preserved the event across restart and
forced image recreation, preserved the volume across `down`, and removed it
only with `down --volumes`. Resolved configuration and service logs contained
neither smoke credential. `make check`, focused direct/`_FILE` conflict and
CR/LF newline tests, `go test -race ./...`, ShellCheck 0.11.0, all 19
Playwright Chromium/axe tests, and `git diff --check` pass. No Go API,
migration, dependency, runtime service, secret environment variable, host
mount, privileged mode, custom network, or public image publication was added.
Compose-only controls use `COMPOSE_SIFTAIL_` so Coolify's generated
`.env`/`env_file` does not inject unknown variables from Siftail's reserved
application namespace.

**Authoritative references:** `ARCHITECTURE.md` §§9, 22, 34; `PRODUCT.md`
§19.5.

**Outcome:** Provide a minimal, production-shaped Compose example for local and
generic reverse-proxy deployment.

**Acceptance:**

- Compose defines one Siftail service, one persistent volume, both listener
  boundaries, restart/health behavior, and no external runtime dependency.
- Secrets use documented `_FILE` or local setup workflows and examples contain
  no usable credentials.
- TLS/public URL, trusted proxy CIDRs, ports, upgrades, and data ownership are
  explicit; no identity-header authentication is implied.
- Fresh install, restart, upgrade, and removal preserve or intentionally remove
  state as documented.

**Verification:**

- Validate Compose syntax and run end-to-end create-admin, create-token,
  ingest, browse, restart, health, and clean teardown smoke.
- Test direct/file secret conflicts and volume permissions without printing
  secret content.

**Impact:** Adds deployment documentation/configuration, not a new service.
Operator-facing environment examples become compatibility surface.

**Outcome:** Assemble evidence for a maintainer decision on the first public
dogfood release without automatically publishing it.

**Acceptance:**

- A requirement matrix maps every `PRODUCT.md` §19.5 item and repository
  release gate to automated, measured, and manual evidence.
- Fresh install, all upgrades, backup/restore, Coolify/generic ingestion,
  retry/saturation/disk-full/shutdown, security, browser, performance, and soak
  procedures pass on production artifacts.
- Operator docs and known issues are accurate; unresolved data-loss, recovery,
  security, or unbounded-resource defects block completion.
- Completion produces a release recommendation and limitations, not a tag,
  image push, or `latest` publication.

**Verification:**

- Run every stable-release command and procedure documented in
  `ARCHITECTURE.md`, the full race/browser/migration/recovery suites, artifact
  inspection, and `git diff --check`.
- Record exact artifacts, image digests, environments, commands, results,
  screenshots, benchmarks, soak evidence, and manual checklist outcomes.

**Impact:** Release-gate documentation only unless verification exposes
defects. Marks SFT-050–SFT-058 Done only when the public dogfood evidence is
complete.
