**Completed:** 2026-07-28

**Completed:** 2026-07-28

uncommitted ingestion batch returns `507`, rolls back completely, and is never

degraded. Later authenticated ingestion requests are rejected with `507`

coordinator-serialized transaction inserts and deletes one bounded 64 KiB
internal settings value, requires a real commit, leaves no row, and only then
clears degradation, restores readiness, and records a fixed sanitized recovery
diagnostic. Failed probes are debug-category-only and never recreate, replace,
delete, migrate, or vacuum the database. Real-SQLite tests constrain

### SFT-044 — Implement stopped-server restore with rollback preservation

**Status:** Done
**Milestone:** 0.4.0
**Depends on:** SFT-043
**Issue/PR:** — (direct maintainer implementation)
**Completed:** 2026-07-28
**Completion evidence:** Added the destructive CLI-only `siftail restore
--confirm RESTORE <path>` workflow for verified full and configuration
artifacts. The server and restore command now share an owner-private,
no-symlink, nonblocking advisory maintenance lock held for their entire
database ownership, so restore refuses an active process and server startup
cannot race or enter service during restore. The command verifies the input,
runs a full stopped-current-database compatibility/integrity check, preflights
space for artifact plus current logical database/WAL and 5% or at least 1 MiB
slack, exclusively creates mode-`0700` fixed staging, stream-copies through a
128 KiB buffer into mode `0600`, synchronizes it, and re-verifies the staged
type/checksum.

Before replacement, SQLite's online backup API captures the current database
and all committed WAL state into a verified format-1 full rollback artifact;
sessions are removed. The old database then receives a truncating checkpoint,
all connections close, the main file and directory synchronize, and only
checkpointed sidecars are removed. The staged artifact atomically replaces the
main database. Production open applies supported forward migrations and
refuses newer schemas. One transaction deletes sessions and artifact-only
metadata and records a safe local-operator `restore.apply` audit. Full
integrity, current schema, critical tables/queries, zero sessions, metadata
absence, truncate checkpoint, mode-`0600`, and a second closed-file full check
must pass before the preceding `siftail.db.rollback` is atomically replaced and
re-verified. Configuration restore is complete replacement with empty history,
not a merge.

Ordinary failure or cancellation after replacement reinstalls the verified
pre-restore candidate, removes sessions/metadata, records failed/canceled
audit, validates/checkpoints it, and returns failure. A hard interruption can
leave fixed recovery staging but never intentionally removes both valid
states; server startup and later restore refuse and preserve that directory
for manual recovery. The managed rollback is a verified full artifact. Direct
use of its only path is refused; tests and operator docs copy it to protected
storage and successfully restore that copy. The previous managed rollback
remains untouched until the new active database passes all checks.

Real-SQLite tests restore both types, preserve password/token/config/event
boundaries, validate empty configuration history, verify rollback contents and
permissions, migrate a supported schema-3 artifact to schema 4, reject an
active lock, require exact confirmation, preserve corrupt inputs and crash-left
staging, and inject failure after install, cancellation after install, and
failure immediately before rollback publication. Every injected post-swap
fault restores prior configuration with zero sessions and a typed failure
audit. Round-trip rollback recovery succeeds. The restored database accepts a
new event through the production ingestion writer and returns it through the
History store. CLI tests cover active-process refusal, generic secret/path-free
invalid-artifact errors, sanitized output, application restart/readiness, and
a stopped-server subprocess restore. App/database tests cover lock
serialization, permissions, symlink refusal, active-owner startup refusal, and
preservation of incomplete recovery state. Browser tests cover exact host CLI
guidance, rollback/fresh-login copy, responsive layout, themes, and
accessibility. `go fmt ./...`, `go vet ./...`, `go test -count=1 ./...`, `go
test -race -count=1 ./...`, `npm run frontend-check`, all 18 Chromium tests
(55.0 seconds), and `git diff --check` pass. Domain, architecture, design,
README, and `docs/operations/restores.md` document confirmation, locking,
capacity, replacement, migration, credential/session consequences, failure,
crash recovery, and managed rollback use. No schema migration, dependency,
online restore, automatic down-migration, recursive cleanup, extra process,
runtime service, telemetry, upload, or scheduler was added.

**Authoritative references:** `DOMAIN.md` §26; `ARCHITECTURE.md` §§10, 25, 30;
`DESIGN.md` §21.

**Outcome:** Restore verified full or configuration-only backups only while the
server is stopped, preserving the current database as a recoverable rollback
copy.

**Acceptance:**

- Restore refuses an active server, incompatible schema, invalid artifact, or
  failed integrity check before replacing active state.
- The prior database and relevant WAL state are preserved as an explicitly
  named rollback copy; interruption never silently destroys both states.

- Post-restore migrations, integrity, critical queries, permissions, and
  startup behavior are verified before success.

**Verification:**

- Subprocess/fault tests cover both backup types, active-server refusal,

**Impact:** Destructive maintenance command with recoverable rollback and

### SFT-045 — Define bounded History export contracts and streaming stores

**Status:** Done
**Milestone:** 0.4.0
**Depends on:** SFT-044
**Issue/PR:** — (direct maintainer implementation)
**Completed:** 2026-07-28
**Completion evidence:** Added a concrete `logs.ExportStore` that validates a
typed `HistoryQuery` and shares History's closed, bound-parameter SQL filter
builder for every source/container/level/stream/literal-message/common-field
filter. Export deliberately removes page cursor, direction, and page size,
then streams the complete matching inclusive-from/exclusive-to range in
canonical `event_at_us DESC, id DESC` order with `maximum rows + 1` detection
and no `COUNT(*)`, regex, wildcard, arbitrary JSON/SQL/query language, hidden
wider range, or backup behavior. The existing 31-day range applies. Hard
store maxima are 100,000 events, 256 MiB encoded output, and two minutes;
smaller test/workflow bounds are supported but values above the hard maxima
normalize down.

Defined stable lossless `siftail-text-v1` and NDJSON schema-1 contracts over
the complete canonical event scanner. Both carry local event identity,
event/receive UTC RFC3339Nano timestamps, trusted Server and stable source
identity/labels/alias, optional container observation, stream, canonical and
original level, message, standard padded-base64 raw payload, JSON attributes,
source event ID, and normalized logger/request/error/HTTP fields. Optional
values are explicit `null`. Every NDJSON physical line contains one object and
`schema_version:1`; HTML escaping is disabled for a non-HTML artifact while
JSON escaping preserves hostile/multiline/control content. Text begins with a
version marker and fixed tab-separated header; string cells use reversible
quoted escapes, numbers are decimal, and absence is bare `null`.

Encoding retains one bounded scanned event and encoded row, checks a row's
