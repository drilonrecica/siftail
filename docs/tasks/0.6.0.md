# Siftail `0.6.0` implementation tasks

**Status:** In progress
**Release state:** Unreleased
**Task IDs:** SFT-064–SFT-081
**Milestone authority:** ADR 0005; `DESIGN.md` (rewritten by SFT-064);
`PRODUCT.md` §§7–8

This milestone delivers the maintainer-approved operator-console redesign of
the complete interface. It delivers the scope of SFT-056 (see the
supersession note in `docs/tasks/0.5.0.md`) and adds the interaction and
information-architecture changes accepted in ADR 0005. The stack is
unchanged: Go templates, HTMX, focused vanilla JavaScript, plain CSS,
embedded assets, no production Node runtime.

Milestone-wide verification discipline: only one task may leave the
Playwright suite red at a time; every task runs `make check` and
`make playwright` before it is marked Done; foundation tasks (SFT-065–067)
must produce no intended visual change.

### SFT-066 — Store theme and density as server-side preferences

**Status:** Done
**Milestone:** 0.6.0
**Depends on:** SFT-064
**Issue/PR:** — (direct maintainer implementation)
**Completion evidence:** `POST /preferences` (CSRF/Origin-protected) persists

`data-theme`/`data-density` render server-side on `<html>` including login;

internal suites, and all 19 Playwright tests pass.

**Outcome:** `POST /preferences` persists theme/density in a non-secret
cookie; every page (including login) renders `data-theme`/`data-density`
server-side; the `localStorage` preference code is removed; no first-paint
theme flash; works without JavaScript.

**Acceptance:**

- Hard reload in every theme shows no flash; preferences survive sign-out;
  invalid values are rejected; the cookie contains no secrets.

**Verification:**

- `make check`; Playwright theme assertions pass, plus a reload-persistence
  assertion; manual no-JS preference change.

**Impact:** New authenticated POST route under CSRF/Origin protection;
cookie is additive and non-secret.

### SFT-067 — Vendor the monospace face and token foundation

**Status:** Done
**Milestone:** 0.6.0
**Depends on:** SFT-064
**Issue/PR:** — (direct maintainer implementation)
**Completion evidence:** Vendored the JetBrains Mono variable font (wght
100–800) as latin (31,432 B) and latin-ext (11,676 B) woff2 subsets with the
OFL license at `internal/web/ui/licenses/JetBrainsMono-OFL.txt`, served
same-origin as `font/woff2` with immutable caching. `tokens.css` defines the
complete DESIGN.md §27–28 token system once via `light-dark()` with static
dark fallbacks, the type scale, spacing/radius/shadow tokens (including the
previously undefined shadow tier), and density font sizing; it loads before
`app.css`, which still overrides with the legacy values until SFT-069, so no
visual change occurs. Font preload deliberately deferred to SFT-071/072 when
the face is first consumed (preloading an unused font wastes the fetch).
Binary size 19,642,392 → 19,695,680 bytes (+53,288). Asset-integrity tests
extended to the new files; vet, internal suites, and 19/19 Playwright pass.

**Authoritative references:** `DESIGN.md` §§27.3, 27.5, 28; ADR 0005;
`AGENTS.md` §11.8.

**Outcome:** Subsetted JetBrains Mono woff2 (400/700) and its OFL license
are embedded and served same-origin with correct types and caching;
`tokens.css` defines the complete semantic token system via `light-dark()`
with static dark fallbacks; the undefined `--shadow-sm` class of defect is
impossible (all used tokens defined). No page consumes the new tokens yet.

**Acceptance:**

- Fonts load under the existing CSP with no external request; binary-size
  delta recorded; token values match `DESIGN.md` §27.3 or that table is
  corrected in the same change after AA verification.

**Verification:**

- `make check`; asset-integrity and CSP template tests updated and green;
  contrast check of every token pairing in both themes recorded.

**Impact:** Binary grows by the subsetted font size; documented per image
discipline.
